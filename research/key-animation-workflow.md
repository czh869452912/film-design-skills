# 短片段：从漫画宫格转向 layout 与关键原画

调研日期：2026-10-25。场景目标为最长约 15 秒的片段，重点是画出可执行的动作，而不只是排出镜头表。本轮为方法研究，没有调用生成 API，也没有修改 skill。

## 判断

建议主产物改为“共享 layout 下的关键姿态与必要 breakdown”，附短时间轴预演。宫格继续用来并排审阅；生成时不再要求模型同时决定整页版式、不同时间的动作、身份与空间。

这是结合专业动画流程与本地失败样本作出的工程建议，尚未在本仓库验证其生成成功率。片长短使逐关键姿态修正更可承受，但时长本身不决定镜头数或原画张数。

## 专业流程中对应什么

[Toon Boom 的 layout/posing 说明](https://learn.toonboom.com/modules/layout-cleanup/topic/what-is-layout-posing?c=34) 将这一阶段描述为从分镜通向动画的准备：背景、遮挡层、摄影机和主要姿势，共同组成可供执行的镜头依据。它比“每格配一个剧情句子”更接近本项目所需的产物。

[Toon Boom 的 marked drawings 说明](https://learn.toonboom.com/modules/layout-and-posing/topic/about-marked-drawings?c=34) 区分 key 与 breakdown：前者是动作中重要的姿势；后者解释两姿势之间的运动路径或跟随关系，时间不必处在两者正中。这里的 breakdown 不等于补一张漂亮的中间插图。

本项目无需复制大型动画团队岗位，也不需要先画满 15 秒的所有帧。保留必要镜头设计，先让少量关键图把接触、重心、方向和动作结果说清楚；只有转换仍含糊时才补图。

## 本地测试说明了什么

[v0.6](live-grid-v0.6/report.md) 与 [v0.7](live-v0.7/report.md) 中，整页经常保持角色配色与画法，却漏掉共同托杯、改变地面高度、重复人物或增加格数。小孩／猫回改的八个出场槽对应了八格，这只是可能的混淆迹象，不足以认定机制原因。

由这些图能得到的有限结论：当前“纯文字＋人物中心坐标＋多时间整页”的路径不适合可靠地产出这些精确动作。人物中心的位置不能充分表达手指接触、猫的退后方向、台阶层高和刀路。继续加长提示并没有解决这些问题。

## 推荐的制作方式

### 1. 每个机位建立可复用的 layout

先明确目标画幅、摄影机、地面、道具、人物比例和前后遮挡。同机位只建立一份场景依据，后续姿态都回到它检查。静止摄影机可复用相同背景图层；移动摄影机则需要按摄影路径得到相应视角，不能只锁一张背景。

### 2. 先做能决定动作的姿态

优先处理初态、核心接触／避让状态和结果。核心姿态可能是最难的一张，先把它画清楚，再补“怎样到达／怎样离开”。既有视觉基准用于身份、服装和色彩，姿态草图或摆拍用于动作；两类参考分别承担职责。

以 6 秒递杯为例，候选可以是：

| 图 | 作用 | 必须看见的关系 |
|---|---|---|
| K1 | 起始关键姿态 | 甲持杯；乙尚未碰杯 |
| B1 | 靠近的 breakdown | 杯与乙掌之间仍有空隙，持杯手仍承托 |
| K2 | 核心关键姿态 | 同一只杯同时被甲握住、乙托住 |
| B2 | 放开的 breakdown | 乙已支撑，甲手张开并离开杯侧 |
| K3 | 结果关键姿态 | 乙独持，甲空手收回 |

五张是这个候选动作的需求，不是所有短片的配额。若选择有意省略交接的叙事，可能不需要 K2；但要验证精确交接时，K2 正是不可回避的问题。

### 3. 用可编辑的视觉依据约束绘制

简单动作：同一主画面上移动／重画局部，局部图生图或 inpaint 整理。复杂动作：先用参考摆拍、粗线稿或 3D 人偶确定姿势和道具关系，再生成画面。

3D 或草图不要求成为最终美术。粗略体块、肢体和道具就能提供文字没有给出的空间依据，部分布局可以脚本辅助；关键接触和姿势本身仍需检查。对于刀战，平台与摄影机的 3D 依据通常比反复改“同一高度”的文字更直接；这是方法上的选择，尚非本地实测结论。

### 4. 将一致性落实到可复用素材

保留同一主画面／身份参考，不要让每张图只继承上一张生成结果、无限传递误差。每张关键图都对照共同基准；确需前后姿态参考时，另保留相邻图的角色。

局部编辑的区域应覆盖旧肢体位置、新位置、必要遮挡和影子，避免原来的手留下残影。若要求背景像素严格不变，在最终合成阶段复用背景或仅替换编辑区域；不能把生成工具的“保持不变”描述当像素级保证。

### 5. 在时间轴检查后，再清稿与排宫格

先用保持帧的方式播放关键图，检查动作先后、停顿与切点；叠看相邻图检查体积、支点、道具和路径。必要的转折状态补齐后再精修线条和上色。补间或视频生成不能用于证明缺失的动作设计已经成立。

[Blender 的 onion skinning 文档](https://docs.blender.org/manual/en/5.1/grease_pencil/properties/onion_skinning.html) 展示了前后关键图叠看的工作方式；其 [Grease Pencil](https://www.blender.org/features/story-artist/) 将 2D 绘制置于 3D 场景，适合需要空间依据的粗预演。宫格可以由已确认的独立原画自动排版，保留整体审阅和一致性比较的便利。

## 工具路线比较

| 路线 | 适合解决的问题 | 实际限制 |
|---|---|---|
| 当前 NovelAI＋草图／局部重绘 | 沿用现有动漫画法，只改当前姿态或手部 | 仍需先提供正确布局；强度过低会保留旧姿态，过高可能漂移 |
| 多图编辑模型 | 将身份参考、当前 layout、目标姿态一起作为输入 | 语义编辑仍可能改身份或背景；要实测当前接口支持的输入和区域能力 |
| 3D／线稿＋兼容的 ControlNet | 显式约束身体姿态、场景深度或轮廓 | 工作流与模型须匹配；骨架并不自动表达手与杯的接触或动物动作 |

[NovelAI 官方 inpaint 文档](https://docs.novelai.net/en/image/inpaint/) 支持先在底图上画粗略修改，再对蒙版区域生成；可保留局部姿态并调整细节。它还介绍用画布边缘的参考图辅助绘制。这里应先试“画对关键姿态再整理”，而不是只用原首帧做整图图生图；此前整图方式保留旧姿态，并未测试这个具体流程。

本地 `nai.py` 已有 image、mask、strength 与 inpainting 请求支持；未验证 focused inpainting 的 UI 功能是否在当前 CLI 复现。不能因为技术参数里存在 `controlnet_strength`，就声称当前 NovelAI V5 接口可以输入 OpenPose 控制图。

多图编辑可把 [Qwen 官方图像编辑接口](https://help.aliyun.com/en/model-studio/qwen-image-edit-api) 列为候选：其文档支持多图输入与对象／姿态编辑。这里不推荐仅凭发布示例直接替换后端；应先检查当前地区接口和可用模型，再用同一姿态进行测试。新的模型能力不等于本项目的接触动作一定更好。

[ComfyUI 的 Pose ControlNet 教程](https://docs.comfy.org/tutorials/controlnet/pose-controlnet-2-pass) 演示先以骨架控制姿态，再整理风格和细节；[ControlNet 原作者仓库](https://github.com/lllyasviel/ControlNet) 还展示了深度、边缘、涂鸦等条件。人体骨架、场景深度、手与道具轮廓是不同的信息，需要按问题选择，而非只开一个 pose 开关。

## 最小下一轮实验

先只验证一张“双方共同托住杯”的关键原画。共享同一布局和人物要求，对比：

1. 当前纯文字单帧：基线。
2. 正确的粗手部／道具布局＋NovelAI 局部重绘。
3. 相同布局与人物参考＋可用的多图编辑或结构控制后端。

每条路线先限定相同尝试预算，检查手与杯真实接触、双方承托、数量、身份与局部外观。核心图未通过，就不扩展到整段。核心图通过后再做 K1/K3 和两张必要 breakdown，最后排成宫格及短预演。

若随后更新 skill，应替换当前默认生成分支：以“每镜 layout 与关键原画”为制作单位，以“宫格＋时间轴”为审阅方式。保留原有画格 ID、裁图和动态分镜工具，不再叠加另一套术语繁多的通用流程。
