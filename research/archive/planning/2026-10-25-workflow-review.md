# shot-design：基础分镜流程研究与重构建议

日期：2026-10-25。对象：工作区 shot-design，meta.yaml 标为 0.4.5。

本文针对用户指出的“连基础分镜流程都做得不太好”。依据包括当前入口、14 篇 reference、脚本、示例、A/B 原稿、刀战对照实验和实际联系表，并核查官方制作资料、原始研究及同类项目。下述根因是基于这些材料的诊断；新流程是待验证的设计建议，不能视为已经获得效果提升。

## 1. 判断

目前最值得重做的是**从剧情到画面序列的推导过程**。

技能已积累很多摄影知识，但默认任务像是在完成一套设计文档：给节拍分类、打张力分、设情绪拨盘、选机制、填镜头卡，然后画图验证。人物如何完成动作、观众靠哪些画面读懂动作，以及画图发现问题后怎么改变镜头划分，反而没有得到同等具体的指导。

结果容易是：每一栏都有话可填，每个镜头都有理由，整个场面仍然没有被完整地演出来。

建议以四个变化作为下一版核心：

1. 在选择摄影方案前，先把事件因果与必要的空间关系想清楚。
2. 明确区分节拍、镜头和分镜格；一个镜头可以有多个节拍、多个画格。
3. 把粗分镜提前作为探索工具，允许它推翻镜头表。
4. 用观众能否复述、动作是否连贯、他人是否能画出来来评估流程。

这不是要求每个项目采用统一工业管线。下面给出的是适合此技能当前弱点的默认工作方式；已锁定镜头、非叙事蒙太奇、单镜练习都应按需求缩减。

## 2. 从现有文件能确认的问题

### 2.1 场面调度被分散到逐镜描述里，没有先形成整体动作

当前入口 Step 1 写情绪转折，Step 2 选节奏模板并分配时长，Step 3 设拨盘，Step 4 才在镜头卡中填写 staging。缺少一个能独立检查的“这场戏到底怎么发生”的整体方案。

以 [刀战技能稿](../duel-test/outputs/skill.md) 为例：

- S03：B 三步上阶，从 A 前掠过，刀过肩。
- S04：刃咬鞘，留下白线。
- S05：拉开，A 已经在下段，B 在上段，位置对调。

稿件写出了换位前后，却没有充分指定 A 如何下阶、B 如何越过、接触如何改变两人的运动。动作的关键衔接被交给后续执行者补完。即使每个静帧都画对，过程也未必成立。

基础修复：先用普通动词写出“起始位置 → 谁先做什么 → 对方如何应对 → 身体/道具产生什么结果 → 最终位置”。有空间变化时用小平面图辅助；不必把所有场景升级成 3D 工程。

### 2.2 文档承认 beat ≠ shot，数据与工具却没有充分支持

[beats.md](../shot-design/references/beats.md) 明确说节拍与镜头不同，这是正确的。但 sequence 的 `beat_id` 主要按单镜关联；镜头内另设 `beats`，形成两套含义相近的表示。`storyboard` 是单块，图片通过 S01.png 这类镜头编号查找。

最明显的限制在 [animatic.py](../shot-design/scripts/animatic.py)：每镜读取一张图，把整镜时长赋给它。它能验证静帧持续时间和镜间顺序，却不能充分验证同一镜头里的起势、转折、结果和反应时机。

例如“递杯 → 对方接住 → 原持有人松手”完全可能在一个连续镜头中完成，但至少几个关键状态需要被看见。缺少其中的交接状态，持有权会跳变；把每个状态都切成一个镜头，又会破坏动作流。

基础修复：分开三层。

| 层 | 表示什么 | 何时增加 |
|---|---|---|
| 节拍 beat | 行动、理解或关系发生的有意义变化 | 戏发生新的变化 |
| 镜头 shot | 两次剪切之间连续呈现的一段视听内容 | 观看位置/信息组织值得切换 |
| 画格 panel | 镜头内某个需要明确的状态 | 姿态、位置、表情、接触或构图变化需要展示 |

beat 与 shot 可以多对多；panel 属于 shot。**增加画格不自动增加切点。**

### 2.3 把有限场景的经验提升成了通用规定

以下要求在当前文件中有明确表述，但没有足够依据成为所有分镜的门槛：

| 当前要求 | 对基础流程的影响 | 建议替换 |
|---|---|---|
| 高潮位于 70–85% | 在尚未理解场景时先安排固定形状 | 明确本段的注意力和变化；需要高潮时再决定位置 |
| 每段必须有 hold 和 snap，不能均分 | 对话、仪式、重复、观察性镜头容易被误修 | 时长应来自表演、信息和声音；同长与变长均可成立 |
| 一镜有两个事实就拆镜 | 把自然因果链拆碎，增加多余镜头 | 判断观众能否在同一观看过程中读懂，再选加画格、调度、延时或切镜 |
| 每个事实约需 2.5 秒 | 把理解时间当固定常数 | 看信息显著度、熟悉度、画面复杂度和实际播放 |
| 只改变距离就改用运镜 | 限制合理的切近景、反应特写和强调 | 比较切近与移动的叙事效果、时长和连贯性 |
| 一段必须有一次情绪反向设置 | 容易为了新颖加设计 | 反向设置是选项，服务情境时才用 |
| 角色大小关系只能靠摄影机改变 | 排除了演员前进、退让、起身、坐下等基础调度 | 演员、摄影机和场景均可改变画面关系 |

单镜限制一个核心动作可以是某些生成任务的简化建议，但“核心动作”应允许自然子动作。例如“取杯喝水”不能仅因存在拿、举、饮、放四个动词就被拆成四镜。

建议逐条标注：真正不变量、默认建议、类型策略、模型经验。类型策略和模型经验不进入通用严格校验。

### 2.4 分镜图出场太晚，而且没有充分获得反改设计的权力

入口 Step 6 才画分镜，之前已完成张力、时长、拨盘、机制、方案和镜头卡。`shot-list-spec.md` 又要求：若画格需要新设计决定，先改卡。这可以维护最终一致性，但容易在创作阶段变成“图只是已完成文案的插图”。

现有预演门主要规定生成、标注、拼接、查看；缺少更具体的修改动作：看不懂时应该合镜还是拆镜？增加中间格是否足够？是否需要删掉之前最喜欢的特写？

我查看了 [技能版分镜联系表](../duel-test/previs/skill-sheet.png)：S02 的标签写 MCU，画面主要是裁头后的身体和道具；S04 在一张图片里出现了分隔画框。文字声明与实际画面不一致，叠加标注不会自动解决它。这里同时有图像执行问题与验收落实问题，不能只归咎于分镜设计。

基础修复：先做低成本粗板，尽早通读全段；用粗板决定镜头划分。发现问题后，按“改动作/改调度 → 改取景 → 补关键格 → 合并或拆镜”选择最小有效修改，最终再同步文档。

### 2.5 校验器测到的是声明情况，不能替代导演判断

当前 [cut_checks](../shot-design/scripts/shotlist.py) 的部分逻辑：

- emotion：前后镜都有非空 `emotion.target`。
- story：本镜有 purpose，对应节拍有 knowledge_change。
- rhythm：时长处于 1.2–6 秒。
- eye_trace：有 focus 和 matches 字符串。
- screen_plane：有景别字符串。
- space：有运动方向，或有 negative_space 字符串。

这些判断不能证明情绪成立、视线衔接成立或空间连续。脚本注释也承认这是 readiness 而非 quality，但 100/100 的展示以及实验稿中的满分引用，容易产生过强的成功信号。

本次做了一个仅在内存中的反例探针：取刀战 S01/S02，将后一镜人物内容改成冲突描述，把情绪与目的改成占位文字，焦点改成无关细节；保留检查所需字段。结果六项仍为 true，readiness 仍为 100。这个结果证明上述函数识别不了此类内容矛盾，**不代表完整 validator 的每一项都被测试或绕过**。

另一个落差：文字规定预演门必须真正有图、有 animatic 并看过，但代码只在 3 镜以上检查是否 `any` 一镜有 storyboard 字典，或存在 waiver。它不验证所有实际画格、文件或观看情况；这不能作为“已预演”证明。

建议：结构校验保留；把分数改成明确的字段缺失报告。人工/视觉判断单列为“未检查、发现问题、已复查”，并附具体镜头、画格和修改记录。无需给每次简单任务强制增加评审文书。

### 2.6 现有 A/B 对基础分镜改善的支持弱于总分给人的感觉

由 [原评分表](../ab-test/report.md) 重算：

| 组 | 原始基线 / 技能 | 去掉风险意识后的基线 / 技能 |
|---|---|---|
| A 情绪 | 32 / 36 | 31 / 31 |
| B 动作 | 30 / 37 | 29 / 32 |

A 组的全部分差来自风险意识；B 组仍有 3 分优势。风险预案有实际价值，但这组结果不能单独证明基础分镜更强。去掉一个维度也不是新的独立实验，仅用于理解原分数的构成。

“有机制命名”“有显式节拍”等结构检查又与技能规定高度重合。没有这些术语的作品，也可能拥有清晰的节奏和调度。对照实验还存在格式、风格、首帧和转写混杂，原报告已记录不少限制。

本次原有脚本 selftest 为 5/5 通过，包括当前环境下的 animatic 测试。它证明现有工具回归通过；不说明使用者能通过这套流程做出清楚的分镜。

## 3. 外部资料带来的具体修正

### 3.1 专业分镜采用粗到细的探索，画图参与构思

Disney 官方展示从剧本缩略图、粗略缩略图到更明确图稿的演进；故事艺术家同时处理情绪、表演、时间、调度和取景。[Disney：Story](https://www.disneyanimation.com/process/story/)

Pixar 与 Khan Academy 的练习把场景拆为小节拍，再通过简化图画探索 staging、framing 和 motion。其课程还将 pitching、反馈、重画和 editorial 作为反复完善故事的过程。[Storyboarding 练习](https://www.khanacademy.org/computing/pixar/storytelling/film-grammar/a/exercise-5-film)、[课程总览](https://www.khanacademy.org/computing/pixar/storytelling)

迁移到本技能：粗板应提早出现，镜头表允许修改；不能等大量字段填完才第一次看画面。

### 3.2 先粗略走完整段，再精修，避免过早锁定节奏

Toon Boom 对 Tim Hodge 的原始访谈描述了读剧本、理解语气、画缩略图、快速走完整段、再回头调整铺垫的工作方式；他也谈到过早画精和过早定时会拖慢工作。[Tim Hodge 访谈](https://www.toonboom.com/tim-hodge-on-storyboarding-for-tv-animation)

迁移：先拿到一个可以完整复述的粗方案，再在播放中调时长。总时长是约束，逐镜小数时长可以晚定。

### 3.3 镜头与画格应分层

Toon Boom 的官方术语资料区分 shot/scene 与 panel：画格表现具体动作或时刻，一个镜头可含多个画格。动画软件中的 scene 与日常叙事中的 scene 也未必同义，技能应先定义自己采用的术语。[What is a Panel?](https://learn.toonboom.com/modules/storyboard-concepts/topic/what-is-a-panel)、[Shots, Scenes, and Panels](https://learn.toonboom.com/modules/intro-to-storyboarding/topic/what-are-shots-scenes-and-panels)

注：这些页面的检索摘要可读，但本次部分正文抓取返回 403/404；不据此扩展到其未核查的软件细节。

### 3.4 空间与摄影是相互推敲的，不是锁死文案后的执行

Disney 的 Layout 说明把角色、场景、道具与摄影机放在一起处理，并明确讨论通过增、删、合并镜头来提高叙事清楚程度。[Disney：Layout](https://www.disneyanimation.com/process/layout/)

工作区 Katz 原书提取文本的 Script Analysis / Shot Plan 部分，也先谈整体调度与视觉动作、再谈编号镜头，并强调存在多种工作方法。[本地原始提取文本](../build/extracted/shotbyshot_p001-160/full.md)

据此提出“先建立最低限度的动作与空间依据”，并不表示专业制作必须在任何画图之前锁定全部 blocking。调度、粗板和摄影需要来回修正。

### 3.5 连续性应关注事件理解，不能只维护银幕方向字符串

Magliano 与 Zacks 对叙事电影的研究发现，动作不连续对被试的事件分段影响大于其研究中的时空不连续。这提示本技能，应优先检查观众是否仍在理解同一个行动。[原始研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC3208769/)

应用推论：检查“上一镜动作到哪里了，下一镜从哪里接”，不应只检查 L→R 是否相同。该研究没有提供本技能的镜数、秒数或高潮位置公式。

### 3.6 新研究支持显式空间，但没有证明加结构就会更好

PACE 将剧本证据、实体、空间和摄影机分层表达，并通过几何测量检查取景。其结果也报告了取景控制与动作呈现的取舍，转场、运动和人评仍有未解决部分。[PACE，2026-09 预印本](https://arxiv.org/abs/2609.19853)

StoryBlender 则研究共享空间和可编辑 3D 场景以维持跨镜一致性。[作者项目页](https://engineeringai-lab.github.io/StoryBlender/)

迁移范围：共享场景事实、明确状态、区分实体与单镜变量值得借鉴；当前没必要直接引入 3D、代理编排或复杂编译器。这两项研究都不能证明本文草案已改善分镜质量。

### 3.7 Skill 应提供决策帮助，评测应检验可观察的行为

Anthropic 官方建议先在代表任务上观察能力缺口，再增量构建技能，并按需加载资源。[Agent Skills 工程文章](https://www.anthropic.com/research/equipping-agents-for-the-real-world-with-agent-skills)

LLM 评委存在位置、篇幅、自偏好等已知偏差；匿名也不能消除所有混杂。[MT-Bench 原始论文](https://arxiv.org/abs/2306.05685)

对本技能：默认不要求读多篇理论或输出全部过程；测试应允许基线用相同格式回答，评分重点放在读者实际看懂了什么。

### 3.8 同类 skill 可作候选设计参考，不是已证实的最佳实践

重新查看了项目已引用的 [ai-film-skills](https://github.com/62656456/ai-film-skills) 与 Serge Shima 的 [visual-skills dramaturgy](https://github.com/smixs/visual-skills/blob/main/video/references/dramaturgy.md)。它们分别提供模块化生产思路与意图、空间、视线等决策提示；后者同样包含不少强制配方。

建议借用“问什么问题”的思路，不继续导入更多“每镜必须几件事、每段固定几个阶段”。这些项目的存在与文档完整度不构成对本技能的效果证明。本次草案未复制它们的文字或代码。

## 4. 建议的新默认流程

### A. 读场景：明确输入事实和解释空间

确认谁在场、什么发生、必须保留什么、这次交付到文字还是图。角色意图、视点或结局不确定且会改变方案时才追问；可逆的小选择写明假设继续。

已有剧本不必重写剧情，纯展示镜头不强加人物冲突。未指定模型时不默认 H3；未指定时长时不自动把任何场景压成 10 秒。

### B. 走动作：先检查这件事是否发生得完整

用日常动词写出最小事件链。动作戏补起点、路径、受力或避让、终点；对话戏补视线、停顿与决定；道具变化补持有人和状态。

有移动、接触或多人位置关系时，提供够用的小平面图/调度说明；简单定镜可用一句位置描述。世界位置和画面左右分开记录，后者由机位决定。

产物不是长剧本，而是能回答“如果不剪辑，演员如何把这一段演完”的简明方案。

### C. 组织观看：挑选需要呈现和需要省略的证据

对关键变化问：观众必须看到什么？什么时候看到？跟随谁的注意力？保留同框是否比切开更清楚？

在有真实分歧处比较少量方案。例如刀战是完整看见闪避，还是留在 B 脸上听见落空；不必为每个已明确镜头凑 3 个备选。

新增切点的依据是观看价值：改变注意力、强调反应、重新分配信息、压缩时间等。同一镜头能清楚完成的连续动作，先考虑调度与多个画格。

### D. 做粗板：用画面推导镜头表

以缩略图、简单线稿、站位草图或明确标为待绘的画格说明走完整段。能画时优先低成本画出关系；不能生成图时交付明确的文字分镜，不假称已经看图通过。

给镜头和画格独立编号，如 S02-P01、S02-P02。画格数量来自状态变化，不是每镜统一三格。

通读时遮住解释性标题，检查角色、动作、道具、空间和结果是否仍然清楚。若戏依赖声音，同时提供最小声音提示，避免把默片复述误当所有视听作品的唯一标准。

### E. 修剪与定时：先修改关系，再加工文件

看不懂先定位是漏动作、看不见关键部位、画面焦点错、还是镜头顺序错，再决定补格、改取景、合镜或拆镜。

粗板能读后，用表演、台词、临时声音或播放调整画格时间，继而得到镜头时间。需要 animatic 时按画格串接；同镜换画格不等于新增剪切。

### F. 交付：按用户需求输出到相应层

默认以“镜头/画格、画面与动作、摄影机与构图、声音/剪接、必要时长”组成简表。JSON、机制编号、焦距和参考包只在后续确实使用时增加。

若用户要 AI 视频，再调用独立的模型适配层。把已成立的观看方案映射到生成能力，允许协商修改；不把单次模型故障写进通用电影语言。

## 5. 文件与代码的改进顺序

| 优先级 | 对象 | 修改目标 | 验收方式 |
|---|---|---|---|
| P0 | SKILL.md | 用上述决策流程替换当前强制九步；入口只保留高频判断 | 新用户请求不用查机制库也能完成基本分镜 |
| P0 | beats / rhythm / emotion / QC | 移除通用化的数值配方，保留为有条件策略；消除规则冲突 | 单镜、多格、等时长、无高潮的合理案例不再被误判 |
| P0 | 示例 | 增加一个有“初稿问题 → 粗板 → 修改”的完整案例 | 读者看到选择如何改变，而不是只看到最终稿的理由 |
| P0 | 评测 rubric | 从“是否写出术语/风险栏”改为任务事实与观众理解 | 去除说明文字后仍能判断事件和因果 |

| P1 | animatic.py | 优先读取 panels，按格时长串联，保留 shot 分组与边界 | 同镜多格不会被算作多镜，格时长合计正确 |
| P1 | annotate / refpack | 区分镜头号与格号；参考图选择由模型适配决定 | 多格不会覆盖同名文件，也不会把格号错当镜头号 |
| P1 | validator | 仅硬检 ID、引用、总时长、资源路径等可确定条件 | 结构通过与视觉复查清楚区分 |
| P2 | 知识库 | 按动作、对话、揭示等问题检索；机制为可选词汇 | 实际卡住时能快速找到帮助，不默认全读 |

示意数据结构，而非要求用户手填的固定表：

```json
{
  "shots": [{
    "id": "S02",
    "beat_ids": ["B02", "B03"],
    "panels": [
      {"id": "S02-P01", "duration_s": 1.0, "image": "S02-P01.png", "action": "B 开始接近"},
      {"id": "S02-P02", "duration_s": 1.2, "image": "S02-P02.png", "action": "A 避让，B 的动作继续"}
    ]
  }]
}
```

推荐以格时长求和得到镜头时长，减少重复存储；若兼容旧格式必须同时保留，则检查两者相等。静态镜头一格即可。不在 schema 里强制每格拥有新信息、情绪、声音和机制。

## 6. 下一轮如何检验“基础流程确实变好”

先做小型诊断集，不花视频生成费用。建议 8 类题：

1. 单镜递杯：不能用拆镜代替明确交接。
2. 两人对话，一方作决定：镜头不必跟着说话人机械交替。
3. 同框等待，一个人离开：变化靠调度而非默认推近。
4. 跨镜递钥匙：接手、松手、持有人能够接上。
5. 两人交错而过：世界路径、屏幕方向与机位相容。
6. 一次闪避或碰撞：起因、动作结果与后续状态清楚。
7. 连续长镜内部揭示：可多格，不能把揭示自动切成新镜。
8. 产品或氛围蒙太奇：不强加人物欲望、剧情反转和高潮配比。

对照：无技能、当前版本、精简草案。相同任务、模型、交付格式和大致输出预算，每题建议多次采样；先以少量任务找流程故障，再决定是否扩展。

主要看：

- **事件复述**：不知道原意的读者，能否说清谁做了什么、发生了什么变化。
- **动作接续**：有没有姿态跳变、无来由换位、持有权断裂；有意省略是否能理解。
- **可绘制性**：另一位执行者是否仍需发明关键动作、位置或取景。
- **粗板读解**：遮住解释段落后，必要的画面和声音是否足以支持目标理解。
- **修订能力**：指出一个实际问题后，能否改到对应镜头/画格，而不是增加形容词和规则。
- **操作负担**：不必要追问、文件数、步骤数及用户需要纠正的关键决定。

LLM 可辅助，但不能拿“有 beats/M-ID/fallback”替代上述结果。配对呈现要交换顺序；评审保留具体证据，用户/画师反馈单独记录。已有刀战与两组 A/B 用作开发回归，再留新题检验，避免针对旧题修规则。
