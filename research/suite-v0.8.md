# v0.8：面向普通创作者的影视设计技能体系

日期：2026-10-25。结合 [关键原画调研](key-animation-workflow.md)、[社区工具与导演能力调研](ai-drama-directing-landscape.md)，按用户最新要求实施：帮助普通人参与专业的分镜、画面与导演设计；图片和视频模型均可替换。

## 实际改动

将原单技能改为五个可独立进入的技能：

| 技能 | 主要职责 | 本次新增或调整 |
|---|---|---|
| `film-direction` | 与人共同发展电影化表达 | 主动推荐拍法、用易懂的观看差异引导选择；加入画面形式、光色、声音与局部反馈推演 |
| `shot-design` | 调度、摄影、画框与镜序 | 保留核心工具；深化起点／变化／终点构图与运动；加入“接杯但不让步”的分镜 |
| `keyframe-design` | layout、构图、关键原画 | 共同视觉基准、关键瞬间与必要 breakdown；先解决最关键画面，再扩展；宫格为审阅视图 |
| `screen-media` | 可替换的模型执行 | 按使用者可提供的能力选择输入；图片／视频可分用模型；明确参考职责与执行损失 |
| `animatic-review` | 时间、剪接、声音与实际观看回改 | 从已有素材进入；区分动作清楚与表达成立；按最早失效处回改 |

没有增加只转发任务的总控、强制剧本阶段、资产平台或多 Agent 剧组。导演共创自身提供实质创作能力；已有原画或视频可以绕过它直接进入当前问题。用户不需要先理解机位参数才能得到一版拍法。

方法不局限于功能性“把事说清”：新指导明确要求画面本身的完成度，组织主体尺度、空区、层次、明暗、色彩、摄影路径与声画关系，允许大胆摄影、静止、等待和省略。粗图也可以帮助用户发现自己真正想要的表达。

## 模型解耦与工具

- 从通用 `SKILL.md`、方法参考和元数据中移除特定供应商的默认路线。数据仍用 shot／panel／参考用途描述，模型 API 字段不成为必填项。
- 原 `pageboard.py` 与整页人物槽说明迁到 `integrations/novelai/`。适配器只在用户选择对应工具时使用，不安装进通用技能目录。
- H3 实验与已生成素材继续作为历史证据；没有新建 H3 默认执行层。不同用户可提供不同图片和视频模型。
- 本地工具仍集中在 `shot-design/scripts`，其他技能在可用时使用；它们独立交付文字设计或用现有编辑工具时不必依赖这些脚本。
- 新增 `board.py`：把实际独立图片按原顺序排宫格，等比留边、保留原图内容、shot／panel、源摘要与画布坐标；缺图和覆盖输出在写入前拒绝，排版不会认证内容通过。

`screen-media` 按当前入口实际能力工作：首帧不冒充首尾受控，多参考不冒充时间关键帧，结构条件需兼容。供应商的时长、槽位或独立生成接缝要求不自动变成导演规则。实际限制影响重要表达时，保留原意并说明替代的损失。

## 执行的验证

### 结构与离线工具

- 五个技能均通过 `skill-creator` 的 `quick_validate.py`；UI 名称、说明长度、默认调用名称和本地方法链接核对通过。
- 通用技能运行说明中没有供应商特定模型名；可选适配与历史署名单独保留。
- 通用工具回归：8 组通过，包括新旧示例、44 个渲染路径、未定时草稿、非法输入拒绝、真实图片路径与参考包，以及实际解码的 24 帧顺序与音频补齐。
- 新宫格测试使用宽图、竖图和不同镜头的图片，核对边角像素没有裁掉、ID 保留、原文件字节未改、缺图与覆盖被拒绝。
- 可选 NovelAI 适配回归独立通过，仍检查逐次出场坐标、真实边框裁图、原图摘要和内容认可分离。

### 应用新方法的自检推演

这是同一作者实际展开并检查的设计，**不是独立模型前测或盲评**。不以此宣称导演质量或生成成功率提高。

| 请求／情境 | 实际处理及检查 |
|---|---|
| 普通人：“甲递杯乙接，接受好意却不先让步；别煽情，十二秒内” | 给出同框与末尾揭示两种观看方案，并推荐同框。保存完整分镜 JSON：同框版 1 镜 4 格、末尾揭示版 2 镜 2 格，均为 8 秒；通过严格与时间校验，实际渲染为分镜表 |
| “再疏远些，但别改表情” | 同框版保持回避视线和交接事实，改身体距离、杯跨越空区和手撤回各自一侧；没有追加争吵、对白或微笑。构图是否兼顾手与脸仍待绘制 |
| “图像模型能多图编辑，视频只有首帧输入”这一假设能力情境 | 按身份／layout／姿态组织图片依据；视频提供真正首帧和动作过程，末帧只记为目标，时长范围不明时不编参数。不把假设模型写成当前已配置账号 |
| 从既有失败的猫分镜进入 | 实际打开 v0.7 原图：右上和右下存在重复猫与桌体延伸，不能解释成同一只猫向左退到原桌下。问题首先在原画空间执行，不能靠调格时长或加运镜解决；以现有裁图运行新宫格工具，输出仍标记未评审，没有把旧图翻为成功 |
| 四件器物，每件两秒，同等比较 | 沿用现有展示示例，4 镜各 2 秒；工具检查与渲染通过。不强加关系弧光、悬念、起承转合或默认特写高潮 |
| 只有明确画面方案、只需要适配提示词 | 可直接进入媒体执行，保留当前设计与未知能力，不要求先做导演问卷、完整资产库或重复分镜阶段 |

前两版可查看公开示例：[同框版分镜](../examples/directing-comparison/same-frame.md)、[末尾揭示版分镜](../examples/directing-comparison/reveal-late.md)。旧失败图重新排版（本地产物 `artifacts/suite-v0.8/walkthrough/FAILED-existing-cat-review.png`） 仅验证排版与溯源，不是新生成结果。

这些输出显示了如何将表达差异展开为镜序与画格，但没有实际绘制新原画、生成新视频或取得普通观众反馈。精确动作、画面完成度与观看效果仍需真实制作验证。历史失败继续有效。

## 安装与恢复

升级前确认原安装与 v0.7 源码 23 个非缓存文件完全一致，再备份原源码、安装与哈希到 `artifacts/suite-v0.8/before/`。五个技能同步到本机同一技能根目录；旧版已移出核心的文件按原拥有文件清单移除，未将研究、可选适配或历史实验混入安装。

安装后按文件哈希核对源码与安装，保存记录到 `artifacts/suite-v0.8/installation.json`；运行安装副本的结构检查与通用工具回归。没有修改密钥、账号或全局宿主设置。

## 发布整理

发布前补齐根目录许可、五个技能的署名说明、版本记录、公开分镜对照与实验报告静态图，移除当前报告对未发布本机素材的链接。完整视频、书籍／OCR、模型客户端和账号配置仍不发布。

`tools/build_release.py` 只打包五个通用技能、许可、依赖与安装说明，生成文件 SHA256 清单及压缩包校验值。同一源码重复打包的 ZIP 字节相同；解压到临时目录后单独运行 8 组回归全部通过。仓库附 CI 执行通用工具、可选适配与打包检查。
