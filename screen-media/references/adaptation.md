# 按能力适配图片与视频模型

## 最小视觉任务

用现有工作稿承载即可，不强制增加另一套 JSON。当前任务需要的内容应清楚：

- 对应镜头／画格、图片瞬间或视频起终与过程。
- 目标画幅、观看顺序、构图／动作／光色／声音中不可丢失的关系。
- 真实参考路径及其身份、造型、布局、姿态、风格、起终帧等用途。
- 本次修改范围、锁定内容、目标时长，以及仍待验证的事项。

比如“接受却不对视”需要同时保留手和脸的行为；“最后才知道”要求前面画面不得泄露对应物件。不要在提示词翻译中只保留人物和色调，丢掉这些表达关系。

## 能力影响执行，不冒充导演法则

| 当前可用能力 | 可采用的输入方式 | 需说明的边界 |
|---|---|---|
| 文生图 | 精确描述一个瞬间、画框和可见证据 | 外观与复杂姿态可能漂移；seed 不保证身份 |
| 多参考图片 | 按用途组织真实参考并写清职责 | 不能承诺模型严格隔离参考的身份、画风与构图 |
| 图像编辑／区域重绘 | 主图＋明确修改；区域输入仅在支持时传入 | 小蒙版可能容不下新姿态，未编辑区也未必像素不变 |
| 姿态／深度／线稿条件 | 提供兼容模型实际接受的结构输入 | 人体骨架不等于手与杯接触，接口名相似不代表兼容 |
| 仅首帧视频 | 起始图＋后续动作、摄影与声音要求 | 不能宣称末帧和中间姿态已被锁定 |
| 首尾帧视频 | 正确起终图＋过渡过程 | 首尾正确不证明路径、支撑与时间正确 |
| 多参考视频 | 分别绑定身份、场景或构图等可支持用途 | 普通参考不自动是时间关键帧 |
| 多镜头／时间控制 | 按实际语法表达已选镜序 | 一个生成任务可含多镜，一镜也可跨技术任务；任务边界不自动是剪切 |

核对这次实际入口是否暴露能力；不要把网页 UI 的功能等同于当前 API。图片和视频可以用不同供应商，只要原画、身份、构图和输出规格能衔接。

## 提示转换

自然语言模型用清楚的画面与过程；标签模型区分全局、人物与布局；有单独字段时分别提交声音、时长或负向约束。未知权重、CFG、参考槽位、时长范围不要猜。不支持的控制明确记为未知或不支持，选择可执行替代。

已有首帧时重点补运动与变化，避免外观重述与参考冲突；尚无图片时不能写“严格遵循图 1”。用于审阅的宫格、箭头与字幕不自动成为视频首帧，需确认模型如何使用这种输入。

## 小规模验证与修正

先选最能判断路线的一张图或一段短视频。控制预算和共享输入，检查：表达关系、人物与物件、支撑／路径、取景、显露时间、声音。普通使用不强制多模型竞赛。

只有手错而其他部分可用时优先改局部；构图根本不支持目标时回到画面设计。模型不能稳定执行某动作时，说明替代是否改变了完整可见性、节奏或风格；不能悄悄用切黑、镜外完成或新增动作绕过用户要求。
